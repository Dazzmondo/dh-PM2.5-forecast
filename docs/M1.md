# Six-Hour Urban PM2.5 Forecasting Across Ireland and Europe

**Milestone 1: data storage, versioning, preprocessing and splits**

**Repository:** [github.com/Dazzmondo/dh-PM2.5-forecast](https://github.com/Dazzmondo/dh-PM2.5-forecast). This document shows the key code of every script as short excerpts, so it can be read on its own.

## Project overview

This project builds an end-to-end AI/ML system that forecasts the **3-hour mean PM2.5 concentration 6 hours ahead** at urban air-quality monitoring stations in Ireland and Europe. Historical measurements from official sources are stored in Google Cloud Storage (GCS), cleaned into one common dataset, turned into features and split chronologically, ready for model training in later milestones.

**Main question:** Can machine learning accurately forecast PM2.5 concentrations 6 hours ahead across different Irish and European cities using historical air-quality measurements?

**Secondary questions:**
1. Can a model trained across several cities generalise to a city not seen during training?
2. Does including geographically and environmentally diverse cities improve or affect generalisation? (A hypothesis to be tested, not an assumption.)

**Planned models:** Persistence baseline → Linear Regression → XGBoost → PyTorch GRU/LSTM (optional). Milestone 1 covers the data pipeline only; no models are trained yet.

## 1. Raw data storage (1.0 point)

**Where:** all original source files are kept, unchanged, in a **Google Cloud Storage (GCS)** bucket under `raw/`, in one folder per source, city and station. The bucket is in the EU multi-region.

**Why GCS:** the raw data are historical files that are read in batches and never updated transactionally, so durable, scalable object storage is the right fit. Keeping the raw files untouched also follows the data-lake principle: if a preprocessing decision turns out to be wrong, the processed data can be regenerated without downloading everything again.

**Upload script:** [`upload_raw_data.py`](https://github.com/Dazzmondo/dh-PM2.5-forecast/blob/main/src/upload_raw_data.py) mirrors the local `raw_data/` folder (same layout) into `raw/`:
- It creates the bucket if it does not exist (EU location, uniform bucket-level access, object versioning on). If an existing bucket has versioning off, it switches it on.
- It computes a SHA-256 checksum of each file *before* uploading. A file already in the bucket with the same checksum is skipped; a file whose content changed is uploaded again as an update, and the earlier copy is kept by bucket versioning.
- It adds one record per uploaded file to `manifests/raw_files.jsonl` (Section 4) and finally compares the number of local files with the number of objects under `raw/`.

**Key code:** the checksum is computed from the file contents, and the manifest decides whether a file is skipped, updated or uploaded as new:

```python
# src/upload_raw_data.py
def sha256_of_file(path: Path) -> str:
    """Fingerprint of a file's contents. Read in 1 MiB chunks so a large file never has to fit in memory."""
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(1 << 20), b""):   # 1 << 20 = 1,048,576 bytes
            h.update(chunk)
    return h.hexdigest()

# excerpt from upload_local_tree(): skip, update or upload each file
checksum = sha256_of_file(local_path)   # computed BEFORE uploading, from the exact file being sent

previous = known_checksums.get(gcs_url)   # checksum recorded when this file was last uploaded (None = new)
if previous == checksum and gcs_path in existing_objects:
    skipped += 1   # unchanged AND still in the bucket: nothing to do
    continue
if previous is not None and previous != checksum:   # same path, different content: a revised file
    print(f"Checksum changed for {relative} - uploading the updated version.")
    updated += 1
else:
    uploaded += 1

record = upload_file(bucket, local_path, gcs_path, checksum, commit)
record["source"] = relative.split("/")[0]   # first folder = the data source: epa, uk_air or eea
new_records.append(record)
```

## 2. Processed data storage and file formats (1.0 point)

Processed data are stored in the same bucket under `processed/`, always as **Apache Parquet**. Raw files keep their original formats (CSV for EPA Ireland, RData for UK-AIR, Parquet for EEA) and the manifests are JSON Lines.

| Path in `processed/` | Contents | Rows |
|---|---|---:|
| `canonical/canonical_hourly.parquet` | Hourly PM2.5 for all 17 stations in one schema, UTC timestamps | 1,180,226 |
| `three_hour/three_hour_aggregated.parquet` | 3-hour mean blocks with the number of valid hours | 400,611 |
| `features/pm25_features.parquet` | Features and target for every usable row, plus the `split` label (the 22 columns of the local feature table + `split`) | 358,142 |
| `splits/train/train.parquet` | Training rows | 123,399 |
| `splits/dev/dev.parquet` | Development rows | 31,192 |
| `splits/test/test.parquet` | Final test rows | 25,944 |
| `splits/held_out/held_out_test.parquet` | 2025 rows of the held-out (unseen) cities | 13,362 |
| `splits/future_update/` | 2026 data for the Milestone 4 update demo | empty until 2026 data are added |

Rows labelled `excluded` (164,245) appear only in `pm25_features.parquet`.

**Why Parquet:** the data are structured time series with many numeric columns that are read repeatedly for analysis and training. Parquet is columnar (only the needed columns are read), compressed, keeps data types (timezone-aware timestamps, floats, integers) and is read directly by pandas, PyArrow and BigQuery. It is a storage choice, separate from the data type: PM2.5 is numerical time-series data whichever format holds it.

**Store script:** [`store_preprocessed_data.py`](https://github.com/Dazzmondo/dh-PM2.5-forecast/blob/main/src/store_preprocessed_data.py) uploads each stage with its row count, uploads `metadata/station_reference.csv`, stops with a clear message if an earlier stage has not been run, and appends a version record to `manifests/dataset_versions.jsonl` (Section 4).

**Key code:** each stage is uploaded as Parquet with its row count, and each split goes to its own folder (a split with no rows, such as `future_update`, is skipped):

```python

# excerpt from main()

        continue
```

## 3. Database / object storage decision (0.5 point)

Different workloads use different tools; nothing is forced into one database.

| Option | Decision | Reason |
|---|---|---|
| GCS object storage | **Used**: the authoritative store for raw data, processed Parquet, manifests and metadata | Historical files read in batches, no transactional updates, durable and scalable |
| Parquet files | **Used** for all processed data | Columnar, compressed and typed; fast analytical reads with pandas and PyArrow |
| BigQuery | **Not used for now** (optional later) | About 319k three-hour rows (944k hourly) are analysed with pandas in seconds, while BigQuery adds setup (datasets, load jobs, IAM). It will be reconsidered later based on workload and educational value |
| Cloud SQL / PostgreSQL | **Not used** | There are no transactional updates or CRUD workloads; the work is batch ingestion, analysis, feature generation and training |
| Sharding / partitioning | **Not needed** | The data stay manageable as single Parquet files; partitioning by year or station can be added later without changing the raw layout |
| Feature store | **Not used** | Feature definitions live in version-controlled code (`feature_extraction.py`); training-serving consistency will be handled in Milestone 4 by reusing the same code |

## 4. Data versioning (0.5 point)

Source organisations can publish revised or corrected measurements, so versions are explicit and nothing is overwritten silently.

**Raw files.** Bucket object versioning is on, and every uploaded file gets one record in `manifests/raw_files.jsonl`:

| Field | Meaning |
|---|---|
| `local_path`, `gcs_path` | Where the file was on the machine and where it went in the bucket |
| `source` | First folder: `epa`, `uk_air` or `eea` |
| `checksum_sha256` | Hash of the file contents, computed before upload |
| `size_bytes`, `file_modified_utc` | File size and last-modified time (the best stand-in for download time) |
| `upload_timestamp_utc` | Time of upload |
| `pipeline_version`, `git_commit` | Code version (`config.py`); the commit gets a `-dirty` suffix if tracked files have uncommitted changes |

These fields are written automatically by `upload_file()` in `upload_raw_data.py`; `pipeline_version` and `git_commit` come from `config.py`, which adds `-dirty` if tracked files have uncommitted changes:

```python
# src/upload_raw_data.py (excerpt from upload_file)
return {
    "local_path": str(local_path),
    "gcs_path": f"gs://{bucket.name}/{gcs_path}",

# src/config.py
def git_commit() -> str:
    """Hash of the code that is running, for the manifests. Gets a "-dirty" suffix
    if tracked files have uncommitted changes, and "unknown" outside a git repo."""
    try:
        # "git rev-parse HEAD" prints the hash of the current commit
        sha = subprocess.run(["git", "rev-parse", "HEAD"], cwd=REPO_ROOT, capture_output=True, text=True, timeout=10)
        if sha.returncode != 0 or not sha.stdout.strip():
            return "unknown"   # not a git repository
        # "status --porcelain" lists modified tracked files; untracked files are ignored,
        # so only uncommitted edits to committed files make the run "dirty"
        changed = subprocess.run(["git", "status", "--porcelain", "--untracked-files=no"], cwd=REPO_ROOT,
                                 capture_output=True, text=True, timeout=10).stdout.strip()
        return sha.stdout.strip() + ("-dirty" if changed else "")
    except Exception:   # git missing or timed out: never let this stop a pipeline run
        return "unknown"
```

**Processed datasets.** Each run of `store_preprocessed_data.py` appends one line to `manifests/dataset_versions.jsonl`:

| Field | Meaning |
|---|---|
| `dataset_run_id`, `created_timestamp_utc` | Identify the run (UTC timestamps) |
| `pipeline_version`, `preprocessing_version`, `feature_version` | Version labels |
| `git_commit` | Code version that produced the data |
| `raw_data_version` | SHA-256 of `raw_files.jsonl`: a fingerprint of exactly which raw files existed |
| `station_reference_sha256` | SHA-256 of `metadata/station_reference.csv` |
| `row_counts`, `config` | Rows per split; the settings used (rolling window, forecast horizon, minimum valid hours, completeness threshold) |
| `outputs` | For every file written: GCS path, SHA-256, size and rows |

The dataset record is built at the end of `main()`. `raw_data_version` is a fingerprint of the raw manifest, so two dataset runs with the same value used exactly the same raw files:

```python
# src/store_preprocessed_data.py
def raw_data_version(bucket):
    """SHA-256 of the raw-file manifest = a fingerprint of exactly which raw files were uploaded."""
    blob = bucket.blob(RAW_MANIFEST)
    if not blob.exists():
        print(f"WARNING: {RAW_MANIFEST} not found - run upload_raw_data.py first; raw_data_version will be null.")
        return None
    return hashlib.sha256(blob.download_as_text().encode("utf-8")).hexdigest()

# excerpt from main()
append_manifest_entry(bucket, {
    "dataset_run_id": now.strftime("%Y%m%dT%H%M%SZ"),
    "pipeline_version": PIPELINE_VERSION,
    "preprocessing_version": PREPROCESSING_VERSION,
    "feature_version": FEATURE_VERSION,
    "git_commit": git_commit(),
    "raw_data_version": raw_data_version(bucket),
    "station_reference_sha256": sha256_of_file(REFERENCE_PATH),
    "row_counts": {k: int(v) for k, v in features["split"].value_counts().items()},
    "config": {
        "rolling_window_blocks": ROLLING_WINDOW_BLOCKS,
        "target_horizon_blocks": TARGET_HORIZON_BLOCKS,
        "aggregation_min_valid_hours": MIN_VALID_HOURS,
        "completeness_threshold": COMPLETENESS_THRESHOLD,
    },
    "outputs": outputs,
    "created_timestamp_utc": now.isoformat(),
})
```

This gives the lineage **raw data version → preprocessing version → feature dataset version → (from Milestone 2) training run → model**, so the question "which exact data, preprocessing code and feature definitions produced this model?" can be answered.

## 5. Data access (1.0 point)

**Sources**

| Source | Data | Format | Stations |
|---|---|---|---|
| EEA Air Quality Download Service | Hourly validated PM2.5 (dataset E1a) | Parquet | Athens, Copenhagen, Madrid, Paris (7) |
| EPA Ireland (airquality.ie) | Provisional hourly PM2.5 | CSV | 6 Irish stations |
| UK-AIR (Defra) | Automatic-monitoring hourly PM2.5 | RData (R data file) | Belfast, Derry, London (4) |

**How the code accesses the data**
- Raw files are read from the local `raw_data/` folder (path in `config.py`); each file is matched to its station through the folder it sits in, as listed in `metadata/station_reference.csv`.
- GCS is accessed with the `google-cloud-storage` client. The project ID and bucket name come from the environment variables `GCP_PROJECT_ID` and `GCS_BUCKET_NAME`; the scripts stop with a clear message if they are not set.
- Credentials use Google **Application Default Credentials** (`gcloud auth application-default login`). No key or password is stored in the code or the repository.
- In Milestone 2 the training code will read the Parquet splits from GCS with pandas (via `gcsfs`).
- Libraries: pandas, NumPy, PyArrow and google-cloud-storage (versions in `requirements.txt`).

**Key code:** the project and bucket come from environment variables, the client uses Application Default Credentials, and the scripts stop if the placeholders were not replaced (`store_preprocessed_data.py` uses the same pattern):

```python
# src/upload_raw_data.py
PROJECT_ID = os.environ.get("GCP_PROJECT_ID", "your-gcp-project-id")
BUCKET_NAME = os.environ.get("GCS_BUCKET_NAME", "your-unique-bucket-name")

def get_client() -> storage.Client:
    """Storage client for the configured project. Credentials come from Application Default
    Credentials (see the module docstring), never from the code."""
    return storage.Client(project=PROJECT_ID)

# src/config.py
def check_gcp_settings(project_id: str, bucket_name: str) -> None:
    """Stop early, with a clear message, if the project/bucket are still the placeholders."""
    if project_id.startswith("your-") or bucket_name.startswith("your-"):
        raise SystemExit("GCP_PROJECT_ID and GCS_BUCKET_NAME are not set. Set them as environment variables "
                         "(PowerShell: $env:GCP_PROJECT_ID=\"...\"; $env:GCS_BUCKET_NAME=\"...\") and run again.")
```

The three raw-data scripts only write to `raw_data/` (the metadata script to `metadata/source_metadata/`), and all four skip files that already exist, retry on errors, write each file through a `.tmp` file, pause between requests, and print a summary (a non-zero exit code if something failed). **UK-AIR uses `.RData` files.** UK-AIR's `robots.txt` disallows automated access to `/datastore/`, where the website's CSV files are stored, so the script downloads UK-AIR's `.RData` files (R data tables, published for the R package `openair`) from `/openair/R_data/`, which is not disallowed. ## 6. Data split / validation strategy (2.0 points)

The data are time series, so the split is **chronological**: a random split would let future observations influence model development.

| Period | Years | Used for |
|---|---|---|
| Training | 2018–2023 (Irish stations: 2022–2023) | Fitting model parameters; time-aware cross-validation may be used inside this period |
| Development | 2024 | Comparing models, tuning hyperparameters, selecting features, early stopping |
| Final test | 2025 | Untouched until final evaluation; never used to choose a model, hyperparameters, features or window length |
| Future update | 2026 | Reserved for the Milestone 4 "new data → retrain → compare with v1" demo |

Approximate shares (training / development / test): non-Irish stations 75% / 12.5% / 12.5%; Irish stations 50% / 25% / 25%, because they only have data from 2022. The result is 358,142 usable rows, 123,399 of them for training, far above the course minimum of 10,000 samples (counts in Section 2).

**Geographic holdout.** Three cities are held out: **Derry** (GB1060A), **London** (Bloomsbury GB0566A, N. Kensington GB0620A) and **Paris** (Gennevilliers FR04002, Saint-Denis FR04058). They are excluded from training and model selection, and only their 2025 rows (`held_out_test`) are used to measure generalisation to unseen cities. This gives two evaluation dimensions: known cities in later years (temporal) and completely unseen cities (spatial). Held-out cities stay unseen across all source systems.

**Cross-validation.** Random k-fold cross-validation over the whole dataset is not used. If cross-validation is needed it will be time-aware and restricted to the training period; the 2024 and 2025 data stay outside it.

**Leakage prevention**
- Lag and rolling features use only the block that has just finished and earlier blocks; the target block never enters a feature.
- A row is labelled only if its input block and its target block (6 hours later) fall in the same period. A row whose input is in late December 2023 but whose target is in January 2024 is `excluded` (70 rows), so no training label comes from the development year. New Year inside the training period is not a boundary.
- Held-out stations never enter train, dev or test; the script stops if one does.
- Steps that learn from data (scaling, encoding, imputation values, feature selection, hyperparameter tuning) will be fitted on training data only and applied unchanged to dev and test (Milestone 2). Deterministic steps (timestamp parsing, station mapping, duplicate removal, 3-hour aggregation) learn nothing from the data, so they run before the split.

**Implementation:** [`create_splits.py`](https://github.com/Dazzmondo/dh-PM2.5-forecast/blob/main/src/create_splits.py) gives every row a `split` label: `train`, `dev`, `test`, `held_out_test`, `future_update` or `excluded`. Training starts in each station's first available year (`availability_start` in `station_reference.csv`, never before 2018), which is how the Irish stations start in 2022 without a special rule. The script stops, writing nothing, if a held-out code is not in `station_reference.csv`, if a held-out station is missing or has no 2025 rows, or if any held-out row ends up in train, dev or test.

```python
# src/create_splits.py (excerpt from assign_splits)

    same_period & (in_period == "future"),                  # 2026 rows: kept for the update demo
    same_period & is_held_out & (in_period == "test"),      # an unseen city's 2025 rows: the unseen-city test
    is_held_out,                                            # every other row of an unseen city: unused
    same_period & (in_period == "test"),
    same_period & (in_period == "dev"),
    same_period & (in_period == "train"),
]
choices = ["future_update", "held_out_test", "excluded", "test", "dev", "train"]
```

**Safety checks** in `main()`: the run stops, writing nothing, if a held-out station leaks into train, dev or test, or has no 2025 rows:

## 7. Feature description (1.0 point)

| Feature | What it is | Type |
|---|---|---|
| `pm25_current` | Mean PM2.5 of the 3-hour block that has just finished when the forecast is made | Continuous, µg/m³ |
| `pm25_lag_1`, `pm25_lag_2`, `pm25_lag_3` | Mean PM2.5 of the 1st, 2nd and 3rd block before the current one (3, 6 and 9 hours earlier) | Continuous, µg/m³ |
| `pm25_rolling_mean`, `pm25_rolling_std` | Mean and standard deviation of the last 8 blocks (24 hours), including the current block | Continuous, µg/m³ |
| `time_block` | 3-hour slot of the day in station-local time: 0 = 00:00–02:59 … 7 = 21:00–23:59 | Integer 0–7 |
| `day_of_week` | Local day of the week, 0 = Monday … 6 = Sunday | Integer |
| `month` | Local calendar month, 1–12 | Integer |
| `season` | Meteorological season: Dec–Feb winter, Mar–May spring, Jun–Aug summer, Sep–Nov autumn | Categorical |
| `city`, `country` | City and country of the station (from `station_reference.csv`) | Categorical |
| `latitude`, `longitude` | Station coordinates | Continuous |
| `target_pm25` | Mean PM2.5 of the block 2 blocks (6 hours) after the current one | Continuous, the target |

The feature table also holds these bookkeeping columns: `station_id`, `timezone`, `block_start_utc`, `local_timestamp`, `pm25_3h_mean`, `valid_hours`, `target_block_start_utc` and, after the split, `split`.

**How the features are built** ([`feature_extraction.py`](https://github.com/Dazzmondo/dh-PM2.5-forecast/blob/main/src/feature_extraction.py)):
- A forecast is issued *after* a 3-hour block has finished, so that block's mean (`pm25_current`) is a known input. Nothing from the target block or later enters any feature.
- Blocks are fixed 3-hour windows on the UTC clock, so "2 blocks ahead" is exactly 6 hours all year, even on daylight-saving change days. Only the time-of-day, weekday, month and season labels use the station's local time (IANA time zone from `station_reference.csv`).
- Each station is first placed on a complete 3-hour grid, so a missing block shows up as a gap instead of silently joining two distant blocks.
- A row needs the current block, all 3 lags, all 8 rolling blocks and the target to be valid. Rows that fail are dropped and nothing is imputed (42,469 rows dropped, 358,142 remain).
- Weather, PM10, NO2 and O3 are left out of the first version to focus on what the PM2.5 record itself can predict.
- Station and city identity could let a model memorise places, which matters for the unseen-city question, so whether they stay model features is a Milestone 2 decision. Latitude and longitude are the more generalisable alternative.

**Key code.** First every station is placed on a complete 3-hour grid, so a missing block is a visible gap:

```python
# src/feature_extraction.py (excerpt from ensure_full_grid)
# every 3-hour block start between this station's first and last block
full_range = pd.date_range(group.index.min(), group.index.max(), freq="3h", tz="UTC")
group = group.reindex(full_range)   # blocks that had no row are added as empty (NaN) rows
group["station_id"] = station_id
for col in STATIC_COLUMNS:
    group[col] = group[col].ffill().bfill()   # copy the station's static values into the added rows
```

Then the lags, rolling statistics and target are added:

```python
# src/feature_extraction.py (excerpt from add_lag_rolling_and_target)
for k in (1, 2, 3):
    df[f"pm25_lag_{k}"] = grouped.shift(k)   # the value k blocks (3k hours) earlier
# mean / std of the last 8 blocks including this one; min_periods=8 gives NaN unless all 8 blocks have a value
df["pm25_rolling_mean"] = grouped.transform(
    lambda s: s.rolling(ROLLING_WINDOW_BLOCKS, min_periods=ROLLING_WINDOW_BLOCKS).mean())
df["pm25_rolling_std"] = grouped.transform(
    lambda s: s.rolling(ROLLING_WINDOW_BLOCKS, min_periods=ROLLING_WINDOW_BLOCKS).std())

# the grid is gap-free, so shifting by N rows is exactly N blocks
df["target_pm25"] = grouped.shift(-TARGET_HORIZON_BLOCKS)   # the value 2 blocks (6 h) LATER: what the model predicts
df["target_block_start_utc"] = df["block_start_utc"] + pd.Timedelta(hours=3 * TARGET_HORIZON_BLOCKS)
```

### Steps 1–4: `canonicalize_raw_data.py`

`canonicalize_raw_data.py` turns the three raw formats into one hourly table (1,180,226 rows, Section 2). Key code for each step:

**Timestamp conventions**

| Source | Label in the file | Time zone | Action |
|---|---|---|---|
| EEA hourly | interval start | UTC+1 (EEA converts every country) | subtract 1 h |
| UK-AIR (`.RData`) | interval start (a number: seconds since 1970) | UTC | none |
| EPA Ireland | hour ending | UTC (both inferred from the data, not documented) | subtract 1 h |

**Step 1, match a file to its station** by the folder it sits in (EEA files are matched by the station code inside the file instead):

```python
# src/canonicalize_raw_data.py
def station_for_folder(file_path: Path, source_dir: Path, folders: "pd.Series"):
    """Which station's raw_folder contains this file? (None if none does.)
    `folders` maps station_id -> raw_folder (relative to source_dir, '/' separated)."""
    rel = file_path.relative_to(source_dir).parent.as_posix()   # the file's folder, relative to raw_data/<source>/
    rel = "" if rel == "." else rel                             # a file directly in the source folder has no sub-folder
    # a file belongs to a station if its folder IS that station's raw_folder or sits inside it
    hits = [sid for sid, folder in folders.items() if rel == folder or rel.startswith(folder + "/")]
    return hits[0] if len(hits) == 1 else None   # exactly one match, otherwise the caller reports the file
```

**Step 2, timestamps.** One hour is subtracted for EPA and EEA (table above). UK-AIR's `.RData` files already label the start of the hour in UTC, so nothing is subtracted:

```python
# src/canonicalize_raw_data.py
# Timestamp conventions. A row stamped 09:00 under "hour ending" covers
# 08:00-09:00; we shift to interval-START so all sources match.
# UK-AIR (.RData): the date is already UTC and labels the START of the hour, so there is nothing to shift.
EPA_TIMESTAMPS_ARE_HOUR_ENDING = True    # INFERRED, not documented: files start each day at 01:00.
#   Could be confirmed by comparing with validated EEA data for the same station.
# EEA: Start/End bound each hour (already interval-start) but the service
# labels them UTC+1 for every country, so we subtract 1h to reach true UTC.
EEA_LABEL_UTC_OFFSET_HOURS = 1

# excerpt from parse_ukair_rdata_file()
# the date is seconds since 1970 in UTC; a different type means the file format has changed
if not pd.api.types.is_numeric_dtype(df["date"]):
    raise ValueError(f"{path}: the 'date' column is {df['date'].dtype}, expected seconds since 1970.")
out = pd.DataFrame({"timestamp_utc": pd.to_datetime(df["date"], unit="s", utc=True),
                    "pm25": pd.to_numeric(df["PM2.5"], errors="coerce"),
                    "sampling_point": path.name})
```

**Step 3, source quality rules.** EEA rows are kept only if their `Validity` flag is 1, 2 or 3; all other rows become missing:

```python
# src/canonicalize_raw_data.py
# EEA Validity codes we accept. 1 = valid. 2 = valid but below the detection
# limit (the measured value is given). 3 = valid, below the detection limit,
# value replaced by half the limit. Everything else (-1, -99, ...) is invalid
# and carries a sentinel value (0, -999, -9999) that must never be used.
EEA_VALID_CODES = (1, 2, 3)

# excerpt from parse_eea_file()
# EEA marks bad hours with a Validity flag; only the codes in EEA_VALID_CODES keep their value
value = pd.to_numeric(df[col["value"]], errors="coerce")
if "validity" in col:
    validity = pd.to_numeric(df[col["validity"]], errors="coerce")  # handles "1" vs 1
    invalid = ~validity.isin(EEA_VALID_CODES)
    below_limit = validity.isin((2, 3))
    if invalid.any():
        print(f"  {path.name}: {int(invalid.sum())} invalid rows (Validity not in {EEA_VALID_CODES}) set to NaN.")
    if below_limit.any():
        print(f"  {path.name}: kept {int(below_limit.sum())} readings flagged valid-but-below-detection-limit.")
    value = value.where(~invalid)
```

**Step 4, duplicates.** Identical duplicate station-hours are dropped; different values for the same station-hour stop the run:

```python
# src/canonicalize_raw_data.py (excerpt from resolve_duplicates)
key = ["station_id", "timestamp_utc"]   # a station-hour is identified by these two columns
dup = canonical[canonical.duplicated(key, keep=False)]   # every row that shares its station-hour with another
if dup.empty:
    return canonical

# per repeated station-hour: how many DIFFERENT PM2.5 values it has (missing values are not counted)
distinct = dup.groupby(key)["pm25"].nunique(dropna=True)
conflicts = distinct[distinct > 1]   # more than one different value = the sources disagree

# ... if there are conflicts, the run stops with an error that lists them; otherwise:
# keep a real value over a NaN when the duplicates are otherwise identical
canonical = (canonical.sort_values(key + ["pm25"], na_position="last")
                      .drop_duplicates(key, keep="first"))
```

### Step 5: `validate_data_quality.py`

The number of hours to expect comes from `availability_start` in `station_reference.csv`, never from the data itself, so a station that lost months of data cannot shrink its own expected period. Years below the threshold are flagged, not removed:

```python
# src/validate_data_quality.py
COMPLETENESS_THRESHOLD = 0.75   # a station-year with a smaller share of valid hours is flagged (not removed)

# excerpt from check_completeness()
for _, st in stations.iterrows():
    avail_start = max(STUDY_START, pd.Timestamp(st["availability_start"], tz="UTC"))   # first hour we expect data
    s_df = df[df["station_id"] == st["station_id"]]   # this station's rows only
    for year in range(avail_start.year, STUDY_END.year + 1):
        # the part of this year inside the expected period (shorter for the first and last year)
        win_start = max(avail_start, pd.Timestamp(f"{year}-01-01 00:00", tz="UTC"))
        win_end = min(STUDY_END, pd.Timestamp(f"{year}-12-31 23:00", tz="UTC"))
        expected = int((win_end - win_start).total_seconds() // 3600) + 1   # hourly values that window should hold
        in_win = s_df[(s_df["timestamp_utc"] >= win_start) & (s_df["timestamp_utc"] <= win_end)]
        valid = int(in_win["pm25"].notna().sum())   # hours that actually have a PM2.5 value
        rows.append({"station_id": st["station_id"], "station_name": st["station_name"], "year": year,
                     "expected_from": win_start.date(), "valid_hours": valid, "expected_hours": expected,
                     "completeness_pct": round(100 * valid / expected, 1),
                     "passes_threshold": valid / expected >= COMPLETENESS_THRESHOLD})
```

### Step 6: `aggregate_to_3hour.py`

`resample("3h")` cuts each station's hourly series into fixed UTC blocks; a block with fewer than `MIN_VALID_HOURS` valid hours gets no mean (it is never filled in):

```python
# src/aggregate_to_3hour.py
MIN_VALID_HOURS = 2  # out of 3, per block

# excerpt from aggregate_station()
group = group.set_index("timestamp_utc").sort_index()   # time-indexed, so resample() can cut it into windows
if group.index.has_duplicates:   # the same hour twice means canonicalize_raw_data.py left a duplicate
    raise SystemExit("Duplicate hours found in the canonical file - re-run canonicalize_raw_data.py, "
                     "which is responsible for resolving them.")
resampled = group["pm25"].resample("3h")   # fixed 3-hour windows, each labelled by its START time
# mean() ignores missing hours; count() is how many hours in the window have a value (0-3)
block_mean, valid_hours = resampled.mean(), resampled.count()
out = pd.DataFrame({"block_start_utc": block_mean.index,
                    "pm25_3h_mean": block_mean.values,
                    "valid_hours": valid_hours.values})
# too few valid hours: the block gets no mean (missing values are never filled in)
out.loc[out["valid_hours"] < MIN_VALID_HOURS, "pm25_3h_mean"] = float("nan")
return out
```

## Known limitations and open decisions

- **EPA data are provisional**, and their hour-ending label and UTC time zone are inferred from the data rather than documented. Both are flagged in the code.
- **Irish stations have only two years of training data** (2022–2023), less depth for time-aware cross-validation. The effect on model performance will be measured.
- **EEA files are whole series.** The EEA API ignores dates, so the canonical table holds 236,261 rows before 2018 (about 20%); they are labelled `excluded` and are not used for training, development or test. Whether to trim them earlier is open.
- **UK-AIR RData and CSV differ slightly.** The `.RData` values differ from the website's CSV values by 0.001 for 0.08% of the values.
- **Gaps:** Kilmainham 2025, Copenhagen 2021 and 2025, London Bloomsbury 2021–2022 (table in Section 10). How stations with no 2025 data are handled in the evaluation is open.
- **Negative readings** (5,666) are kept and reported for now; whether to set them to missing, clip them or keep them is a Milestone 2 decision.
- **To be settled in Milestone 2 using training and development data only:** whether the 2-of-3 valid-hours rule and the 8-block window are right, how much missing data is tolerable, whether station and city identity are model features, and the sequence length for the optional GRU/LSTM.

## Reproduce it yourself

1. Clone the repository and install Python 3.10 or newer.
2. Create a virtual environment and run `pip install -r requirements.txt`.
3. Download the raw data and the metadata: `python src/download_ukair.py`, `python src/download_eea.py`, `python src/download_epa.py` and `python src/download_source_metadata.py` (Section 5). They create the `raw_data/` folders themselves.
4. Sign in to Google Cloud (`gcloud auth application-default login`) and set `GCP_PROJECT_ID` and `GCS_BUCKET_NAME`. The upload script creates the bucket itself.
5. From the repository root, run the seven scripts in order:

```
python src/upload_raw_data.py
python src/canonicalize_raw_data.py
python src/validate_data_quality.py
python src/aggregate_to_3hour.py
python src/feature_extraction.py
python src/create_splits.py
python src/store_preprocessed_data.py
```

The [README](https://github.com/Dazzmondo/dh-PM2.5-forecast/blob/main/README.md#running-the-pipeline-on-your-own-google-cloud-bucket) has the full walkthrough (PowerShell and bash commands, expected output of every script, troubleshooting) at the end.
